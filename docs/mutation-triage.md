# Mutation survivor triage register

The surviving-mutant badge shows a count; this register is the explicit triage
evidence that Issue #176 requires: every survivor from a full mutation run is
listed with a disposition and a reason, so a green aggregate never stands in
for review.

## Review method

fslc treats survivors as a review queue (its mutation notes say survivors are
not a hard failure). Each survivor below was classified by reviewing the
referenced specification and checking whether the mutant changes any modeled
invariant or reachability goal. Classification patterns:

- enum_constant_swap: every swapped target state still satisfies the spec
  invariants and reachability goals (equivalent).
- assignment_remove: the removed assignment is re-established by later
  guarded assignments or the modeled default value (equivalent).
- requires_remove: a sibling precondition or the action ordering provides the
  same guard, so observable behavior is unchanged (redundant).
- requires_negate / equality_operator_flip: the flipped guard cannot be
  reached from a state that violates the governing invariants (equivalent).
- integer_literal / type_bound mutants: the coarse Version abstraction (0..1)
  keeps the sync invariants; the concrete vX.Y.Z spelling is verified by
  cmd/verify-release (equivalent).

## Register schema

The machine-readable block below is validated by check-mutation-triage (part
of mise run check:repository):

- disposition: accepted (reviewed, behavior acceptable), fix-planned
  (accepted for now, a follow-up is planned), or needs-review (untriaged;
  makes the check fail).
- reason: why the disposition applies to this survivor.

Update the register after every full mutation run that changes the survivor
set: run mise run mutate-fsl -- --report <path> and regenerate this block.
